# Native decision proof runs in WASM

The [native external recursive tree contract](../file-formats/native-external-tree.md) verifies complete BFS-ordered collections of proof-carrying splits in native Rust/WASM, using the native induced-child derivation and canonical leaf coverage. It rechecks all proofs and compares full expected trees when supplied. The tree page exposes inert Open, explicit verification, canonical node/leaf tables and exact native tree/proof-bundle downloads. [Native plan delivery, selected-profile audit and geographic rendering](../file-formats/native-external-tree-plan.md) bind the original context and separately supplied unit geometry. Maps use the exact exported plan and existing native renderer, with checked PNG/SVG downloads and source/settings freshness. Automatic tree generation remains unfinished.

The [native external split certificate contract](../file-formats/native-external-split-certificate.md) is implemented in the Rust checker crate and callable from native/WASM boundaries. It recompiles the native models and checks every proof through the concrete VeriPB kernel before issuing an optimal split certificate. Expected-certificate verification also reruns every check. **Issue native split certificate** and **Save native split certificate** expose issuance on the page after fresh generation or saved-proof verification. Imported sessions, counterexamples and incomplete runs cannot enable issuance. Settings/source changes and cancellation retire certificate downloads. The downloaded JSON matches native Rust output; its scope is this split instance. The separate external tree verifier now checks complete recursive collections; tree UI orchestration and native plan delivery remain unfinished.

Saved-package reverification is available through `verifySavedNativeProofRun` in the pipeline module and **Verify saved proofs** on the page. It snapshots imported data, validates the bounded closed file inventory, freshly recompiles the native models, compares each exact OPB/request and native identity, and reruns VeriPB on every proof. It returns a new `bisect-native-proof-reverification-v1` receipt only when all required decisions pass. Stored checker reports and recomputed public hashes do not grant verification authority. It does not rerun the solver or manufacture a bounded exhaustive certificate. The native recursive verifier explicitly requires its existing exhaustive transcript; external certificate schema/adoption remains unfinished. `node scripts/web/test_native_proof_reverification.mjs` checks eight real saved proofs (three/five decisions) and refuses rehashed invalid proofs, forged native IDs, changed models/requests and incomplete counterexamples. Evidence is in `target/native-proof-reverification/evidence.json`.

**Save proof session** retains exact source text, solver limit and any current run evidence in `bisect-native-proof-session-v1` JSON. Source-only sessions can also be saved. **Open proof session** parses bounded UTF-8 in a separate worker, with a 192 MiB file limit, closed root keys, bounded nesting/structure, safe file identifiers, a 128 MiB retained-file ceiling and exact agreement between session sources and retained run files. Opening never compiles models, runs a solver or checks proofs. Imported claims remain unverified; run receipt and checked ZIP exports are disabled. Explicit verification enables a fresh recheck receipt; it does not relabel the old ZIP as a newly generated package. Fresh generation remains available. Changing sources/settings or cancelling retires verification. These experimental proof sessions are separate from the main toolkit's `.bisect` project format. `test_native_proof_session.mjs` exercises structural refusals and exact roundtrip; Chrome covers Save, reload, inert Open, complete rechecking and rejection of a rehashed forged claim.

The local native proof page connects the native compact model compiler, RoundingSat proof generator and independent VeriPB checker in one explicit run. Supply a native split-instance JSON and its discovery JSON, then press **Generate and check native proofs**. Source selection is inert. The page displays the discovery seed recorded in the native method string when it contains one exact unsigned 64-bit seed; the solver has no selectable seed. The seed is retained as decimal text in the run receipt.

The compiler validates the supplied incumbent's instance identity, objective and connectivity and regenerates its native decision files. The run processes population, boundary and canonical decisions and both native low/high population branches when the compiler requires them. Every proof is bound to its **freshly compiled native request and exact OPB bytes before verification**, with instance/discovery IDs, source hashes, request ID, compiler source hash and actual engine artifact hash recorded. Imported solver command templates remain inert text; the solver receives only fixed virtual filenames and supported flags.

For each UNSAT solver verdict, VeriPB must independently accept a complete UNSAT proof for the exact formula. A SAT verdict is independently checked as SAT and reported as a **checked counterexample**; it stops the run and leaves the incumbent unproved. A timeout or unknown result is incomplete. These results cannot export a complete checked proof package. Completed prefixes remain visible in the run receipt. Cancel terminates the worker; changing either source or the time limit retires previous exports. Elapsed watchdogs cover initial compilation/asset loading and checking at 60 seconds each, and solving at the chosen limit plus 30 seconds.

When all required decisions have checked UNSAT proofs, **Save checked proof package** exports the exact input sources, unmodified native OPB/request/manifest files, generated proof logs, solver receipts, checker reports with native request bindings and a complete run manifest. **Save run receipt** also works for checked counterexamples and incomplete runs. The initial compiler manifest and request fields retain their native `not-generated` state as input provenance; the separate checked manifest records the completed proof run without rewriting hash-bound request identities.

The new manifest schema is `bisect-native-proof-run-v1`, with success status `all-native-decisions-checked`. This is evidence for the supplied split instance's native decision package. It is not a replacement for the native recursive tree certificate schema. Recursive certificate adoption, full plan orchestration, global plan optimality, source authenticity and legal compliance remain unfinished. Public hashes describe byte integrity and identities; they are not signatures. Imported receipts must not be trusted without fresh compilation and proof checking.

## Local preview

After the existing engine preview, build/stage the external solver and checker using their [solver guide](wasm-external-proof-solver.md) and [checker guide](wasm-external-proof-checker.md), then run:

```powershell
python scripts/web/stage_native_proof_preview.py
```

Open `http://127.0.0.1:4320/wasm-lab-build/toolkit/native-proof.html`. Staging verifies that the preview engine matches the current tested engine and that solver/checker artifact hashes match their receipts. It records dependency and page/module hashes in `native-proof-build.json`. It does not publish to Cloudflare or change the Rust engine artifact.

Sources are limited to **3 MiB each**, native compiler model packages to **25 MiB**, individual solver OPBs to **8 MiB**, proof logs to **64 MiB**, and complete exported evidence to **128 MiB**. Existing compiler working-set preflight and external tool memory limits remain in force. Solver modules and checker modules are fresh for every decision, with one run worker terminated on cancellation or watchdog expiry. These limits do not bound total browser process memory or establish all-state proof capacity.

## Evidence

```powershell
$env:BISECT_VERIPB = (Resolve-Path target/proof-toolchain/veripb-native-build/release/veripb.exe).Path
node scripts/web/test_native_proof_pipeline_wasm.mjs
$env:BISECT_PLAYWRIGHT_PACKAGES = (Resolve-Path target/browser-test-deps).Path
node scripts/web/test_native_proof_pipeline_browser.mjs
```

Two four-unit fixtures finish all **three** and **five** decisions. The five-decision optimal fixture comes from the actual native bounded exhaustive solver, used only as a test oracle; the production pipeline does not enumerate cuts. Every regenerated OPB/request byte and request identity matches the native compiler host. Thirteen generated proofs across those two runs and an existing noncanonical discovery incumbent are accepted independently by unmodified native VeriPB. The noncanonical incumbent produces a checked SAT canonical predecessor and cannot export a complete package.

A separate **100-unit synthetic grid** reaches its actual one-second boundary solve limit, retaining only the checked population prefix; the unfinished proof cannot certify UNSAT or export a complete package. Additional refusals cover changed OPB/request bytes, swapped request stages, forged hashes, missing branches, invalid discovery identity before solver execution, changed ZIP contents and incomplete decision inventories.

Chrome compares complete run objects, saved receipts and exact ZIP downloads for the three/five-decision fixtures and checked counterexample. It also exercises the actual 100-unit timeout, inert source selection, visible discovery seeds, source/settings freshness, cancellation, a fresh run after cancellation and restrictive CSP. Evidence is in `target/native-proof-pipeline-tests/evidence.json` and `target/native-proof-pipeline-browser/evidence.json`. Emscripten's in-place argument modification is isolated with copied option arrays and a fixed program name, keeping Node/browser receipts identical without host script paths.

The solver's proof-byte ceiling is enforced during virtual-file writes. An output-limit interruption returns an explicit incomplete run with an unverified prefix, and complete-package export remains unavailable. Saved stopped split sessions retain exact instance/discovery/OPB/request bytes, solver metadata, the discovery seed and per-decision time budget. Opening these sessions in the individual proof page remains inert/unverified; incomplete sessions cannot issue certificates or use complete-package verification. A fresh explicit run is required to seek complete evidence.
