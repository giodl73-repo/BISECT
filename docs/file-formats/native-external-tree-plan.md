# Native external tree plan delivery

`export-native-external-tree-plan` connects a fully proved external tree to its original native RCTX and a separately supplied native legal profile. The Rust implementation in `web/proof-checker/src/tree_export.rs` is shared by the native executable and WASM artifact.

The request includes a full `tree_request` (all node sources/proofs and optional expected tree), `context_json`, `profile_json`, `constraints`, `label` and `created_at`. Context/profile sources are limited to 8/3 MiB. The exact original context is hash-validated and its ordered unit IDs, populations and positive integer weighted graph must match the proved root. Every tree proof and parent/child relationship is freshly reverified; a saved tree receipt alone cannot authorize export.

The exporter uses native `DistrictPlan`, RPLAN v0.2 and RCTX serializers. Context unit kind, state/year, source identity, source hashes, subdivisions, demographics and geometry metadata are preserved. Geometry is not invented or copied into a fabricated plan geometry block. District indices come from the verified native leaf assignments. Metadata records the supplied label/time, chosen profile chamber and actual logical producer; native executable/git identities are not fabricated.

Audit uses the original context and supplied profile. Shape, population and contiguity checks are required and distinct; additional native audit constraints are accepted. Profile jurisdiction/year must agree with context metadata and contiguity must be required. Native audit failure prevents successful plan delivery. A proof of local split/tree optimality does not establish compliance with the chosen population policy: the three-seat synthetic fixture has a valid proof but fails a 0.5% population audit. Nonfailure audit outcomes and detailed native warnings remain explicit; no legal authority or source authenticity is asserted.

Output schema `bisect-external-tree-plan-output-v1` contains exact native `exact.rplan`, `exact.rctx`, `external-tree.json`, `audit-certificate.json` and a manifest, with source/file hashes and the verified tree identity. `nativeTreePlanZip` checks a closed file inventory and current hashes before archive creation. The original proof bundle remains necessary for later mathematical verification; these delivery files do not replace node proofs.

The [tree page](http://127.0.0.1:4320/wasm-lab-build/toolkit/native-tree.html) exposes original RCTX/profile selection, label/time and explicit **Verify, export and audit plan** after successful tree verification. Its initial checks are shape, population and contiguity. Source selection is inert. Export rechecks every tree proof and context binding before enabling **Save native plan package**. Changed input/settings, failure, cancellation and watchdog expiry retire package exports. The creation timestamp initially uses the device's current time and is editable. Automatic tree generation remains unfinished.

After successful export, select matching longitude/latitude unit geometry and DPI, then explicitly **Render exported plan map**. This calls the existing native district-map renderer on the exact exported RPLAN; it does not rerun discovery or alter assignments. Geometry selection is inert, with strict UTF-8 and a 64 MiB file ceiling; the native renderer applies its existing geometry profile, geographic bounds and unit/state/year matching checks. No geometry is synthesized from RCTX or the tree. PNG preview bytes and downloadable PNG/SVG artifacts use the existing hash-checked native map delivery helper. PNG displays as an image Blob, with no inline SVG execution. Tree/plan/source/settings changes, failed rendering and cancellation retire prior map exports; object URLs are revoked when retired. A 60-second map watchdog terminates the worker.

`test_native_tree_map.mjs` compares three complete native-host/WASM render results and refuses missing unit geometry. Chrome compares native PNG/SVG downloads, inert geometry selection, visible decoded PNG preview, DPI freshness, missing-geometry refusal and map cancellation. Tests use four separately supplied synthetic geographic cells and do not establish real-state geometry/proof capacity. Evidence is in `target/native-tree-map/evidence.json` and `target/native-tree-browser/evidence.json`.

`test_native_tree_plan.mjs` compares three 2/3/4-seat whole native/WASM packages, original context preservation, native RPLAN validation, exact hashes/ZIPs, and population-audit/profile/year/context-hash/root-population refusals. `test_native_tree_browser.mjs` compares the same exact ZIP downloads in Chrome, inert context/profile selection, label freshness and strict audit refusal, alongside tree verification/roundtrip/cancellation tests. Evidence is in `target/native-tree-plan/evidence.json` and `target/native-tree-browser/evidence.json`. Fixtures are synthetic; statewide delivery/proof capacity is not established.
