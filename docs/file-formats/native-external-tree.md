# Native external recursive tree

`certified-recursive-bisection-external-tree-v1` assembles externally proved native splits into a canonical recursive tree. The concrete native Rust/WASM verifier is `web/proof-checker/src/native_tree.rs`. It calls the real external split verifier for every node and reuses `bisect-ilp::certified_tree::derive_certified_split_children`, which wraps the same induced-child implementation used by existing native bounded trees.

The JSON operation `adopt-native-external-tree` takes `root_instance_json`, a BFS-ordered `nodes` array of `adopt-native-external-split` requests, and optional `expected_tree`. Every node must carry its exact instance/discovery sources and complete proof map. A root must use the empty path and no parent certificate, with 2–1024 seats and exactly `k-1` submitted split nodes. Total proof text is limited to 128 MiB, and existing source, compiler, checker and 192 MiB request limits apply.

The verifier reconstructs the schedule from the root. Before checking a child node, it compares the entire submitted typed instance to the native induced child of the freshly verified parent: unit ordering/universe, populations, weighted edges, seat split, orientation, binary path and parent certificate ID must match. A claimed parent ID or independently valid unrelated child certificate is insufficient. Every node's actual PBP proofs are checked with UNSAT required; no saved checker receipt grants authority.

One-seat leaves are ordered by binary path and receive canonical district indices and native leaf IDs. Leaf units must uniquely and completely cover the root unit set. Output includes the fresh node certificates, leaves and unit-to-district assignments. The tree ID hashes canonical JSON excluding `tree_id`. Supplying `expected_tree` repeats every node proof and graph/lineage/coverage check before comparing the complete fresh result.

The public child-derivation wrapper validates the parent and assignment, connected children and parent ID shape; deriving a child alone is not optimality certification. Production tree verification calls it only after concrete parent proof verification. Existing bounded exhaustive split/tree schemas and transcripts remain unchanged.

The scope is local optimality of each recursive split, exact parent/child lineage and complete one-seat coverage. Global map optimality and source authenticity remain separate work. Automatic generation is available through the explicit browser workflow below. [Native plan delivery and selected-profile audit](native-external-tree-plan.md) are now available through a separate operation requiring the original matching context and fresh proof verification. The browser helper `adoptNativeExternalTree` and tree page expose explicit complete-bundle verification.

Open `http://127.0.0.1:4320/wasm-lab-build/toolkit/native-tree.html` in the local preview. **Open tree proof bundle** accepts the native operation request JSON with all node sources/proofs and optional expected tree. Parsing happens in an isolated worker with a 192 MiB file ceiling, closed root/node fields, bounded nesting/structure, UTF-8 checks and existing source/proof limits. Open is inert and leaves claims unverified. **Verify all tree proofs** runs the concrete Rust verifier before displaying canonical node/leaf tables and enabling native tree or complete proof-bundle downloads. Saved bundles include the fresh expected tree but must be explicitly reverified on reopen. A different file, cancellation, failure or watchdog expiry retires exports. Opening has a 30-second watchdog and full verification has a 60-second watchdog. Nothing is written to arbitrary filesystem paths or executed from imported command text.

`test_native_tree_browser.mjs` checks four exact native downloads, canonical schedule/leaf tables, bundle roundtrip with inert reload/Open, complete reverification, forged parent refusal, cancellation and a fresh recheck. It also checks unknown root keys and malformed UTF-8 refusal. Evidence is in `target/native-tree-browser/evidence.json`. Native plan export/audit and rendering from separately selected geometry are available on the page; no geometry is invented.

`node scripts/web/test_native_external_tree.mjs` creates 2/3/4/5-seat proof fixtures using the actual native bounded tree as a test oracle only. The five-seat case uses eight synthetic path units and exercises deeper unequal-seat scheduling. Production adoption does not enumerate assignments. It generates and checks every node's real compact proofs, compares full native/WASM trees and the native oracle's schedules and leaf fields, repeats expected-tree verification, and refuses forged parent links, altered induced graphs, reordered/missing nodes and forged expected leaf indices. Evidence is in `target/native-external-tree/evidence.json`. These small fixtures do not establish statewide recursive proof capacity.

## Automatic generation

Select a native root split instance JSON, an exact decimal u64 seed, one of the seven shared native refinement profiles, and a 1–120 second budget per proof decision. Optional land adjacency must be a symmetric, duplicate-free subset of the root model graph. Without it, discovery uses the total model graph as land adjacency. Selecting inputs is inert; **Discover, prove and generate tree** starts the worker.

`solve-certified-discovery-instance` calls the existing native discovery engine on each exact instance. Discovery remains an unproved incumbent. The browser generates every required native compact decision proof using RoundingSat and checks it with VeriPB. The concrete Rust operation `derive-native-proved-children` rechecks the parent proofs before calling the shared native induced-child helper. Only these exact derived instances are queued, in breadth-first order; one-seat leaves need no split. Supplied land adjacency is restricted to the derived child unit IDs. The finished bundle undergoes complete native tree verification again before downloads become available.

A checked counterexample or incomplete solver result stops the run without a complete tree certificate. The generator does not silently retry, backtrack or enumerate assignments. Cancellation, source or generation-setting changes retire the result and its export authority. The seed remains visible in the form and progress; each retained native discovery records its seed and refinement. Saved bundles reopen unverified and require explicit fresh verification.

`test_discovery_instance_wasm.mjs` compares 15 complete native/WASM responses across all seven profiles, the maximum u64 seed and a derived child, with invalid seed and land-adjacency refusals. `test_native_tree_generation.mjs` completes two- and four-seat fixtures and stops a three-seat fixture on a checked canonical counterexample. The browser test downloads exactly the same generated bundles, checks settings retirement and cancellation, and confirms counterexample runs cannot export a tree. These synthetic cases establish workflow correspondence, not statewide performance or proof capacity.

## Explicit model preparation

The tree page can prepare a root directly from an original RCTX using `prepare-native-certified-model` in the native proof workspace. Context input is limited to 8 MiB; seats to 2–1024; the exact root source remains limited to 3 MiB. Native validation retains the unit order, populations, topology and edge kinds. **Keep source integer edge weights** is the default and refuses fractional weights without rounding. **Unweighted edge count** explicitly sets model edge weights to one, changes the cut objective, records original-context and policy hashes, and retains the complete original source separately. No geographic objective is certified by this alternative.

Preparation requires an explicit click and runs no discovery or proof. It fills the generation root and native land adjacency, with a matching model context for later plan export. Its ZIP contains `original.rctx`, `model.rctx`, `root-instance.json`, `land-adjacency.json` and a manifest describing the chosen objective and exact file hashes. The original is never overwritten. Changing the source, seats or policy retires prepared outputs and the generated tree. The proof checker uses the engine's `serde_json` float-roundtrip feature so physical-weight context hashes survive parsing exactly.

The solver/checker accept OPB formulas up to 8 MiB while original split/discovery sources remain capped at 3 MiB. Compiler packages, proof logs, evidence archives and WASM linear-memory ceilings retain their separate bounds. `test_native_model_preparation.mjs` compares complete native/WASM preparation for the integer fixture and original 250-tract Rhode Island context, checks preserved source bytes/order/populations/edge kinds and refuses fractional source-integer weights, unknown policies/fields, invalid seats and forged context hashes. The browser checks inert source selection, both exact ZIP downloads, explicit policy selection and settings retirement.

`node scripts/web/test_native_tree_state_capacity.mjs RI IA` retains each original verified state graph and compares native/WASM configured export, explicit model preparation, discovery and compact compilation. No source units are aggregated or reordered. Original geographic contexts are refused identically for fractional weights. Separately prepared edge-count models contain 250 Rhode Island tracts and 896 Iowa tracts. With seed 42, full refinement and a one-second budget, both actual RoundingSat runs time out on the population decision and yield no complete tree certificate. The 8 MiB formula limit allows Iowa's roughly 4 MiB models to reach the solver. On the measured run, total times were about 2.1/3.9 seconds; solver WASM linear memory reached about 19/34 MiB. Node process high-water marks were about 187/328 MiB (Iowa's mark includes earlier work in the same process), not browser-tab or checker-only memory. Evidence and exact sources are under `target/native-tree-state-capacity/{RI,IA}/{geographic,unweighted}`. This short budget test does not establish completion at the default budget or statewide certification capacity.

## Default-budget results and stopped evidence

Set `BISECT_PROOF_SECONDS=30` before running `test_native_tree_state_capacity.mjs RI IA` to use the UI default budget. Non-default budget evidence goes to a separate `target/native-tree-state-capacity-30s` directory, preserving the one-second fixtures. The accepted range is 1–120 seconds per decision. The original geographic weights still refuse under the integer source policy; edge-count model preparation remains explicit.

At 30 seconds, both real state population decisions encountered the 64 MiB proof-byte ceiling. The adapter now intercepts proof-file writes before crossing that ceiling instead of rejecting an already oversized completed log. It returns `solver-proof-output-limit`, no native exit code, an unverified/truncated prefix and exact byte metadata. The measured Rhode Island/Iowa runs stopped in about 15/16 seconds with 67,106,426/67,105,602 retained proof bytes, below the 67,108,864-byte ceiling. No split or tree certificate was issued. These are resource stops, not proofs of infeasibility or optimality. Node process high-water marks include compilation, retained source/proof strings and serialization, and are distinct from solver linear memory.

**Save stopped split evidence** downloads the stopped node as an existing `bisect-native-proof-session-v1` file. This includes that node's exact sources, compiled models/requests, retained prefix and solver metadata, plus its exact seed and budget. It does not represent the completed tree prefix or enable resume. Open it in the individual split page; importing remains inert and cannot authorize complete-package verification or certificate issuance. Source/settings changes and cancellation retire the download. The browser test checks exact small-session bytes, inert reopening, and an actual 250-tract Rhode Island run at 30 seconds reaching the write budget with certificate downloads disabled. Generic solver tests check interruption with a smaller byte budget, refusal by the independent upstream checker for the same formula, and a successful fresh module after interruption.
