# Native ILP summary path binding

Actual desktop ILP packages can save absolute, relative, or parent-relative report locations in their audit summaries. The selected browser files use portable relative names. This candidate preserves the original summary bytes and compares the complete independently audited records using an explicit report selection.

Existing portable comparison runs unchanged first. The compatibility branch requires a sorted, unique report_selection matching the complete independently audited report roster. Each historical report location must end with its complete selected report name. Every record must share the same preceding text, including its final separator; its model location must equal that text plus the independently audited selected model name. Only separator normalization occurs. The historical prefix is opaque text, never an OS path, URL, file handle, or authority to read anything. Relative and parent-relative prefixes are supported because actual desktop producers emit them. URL-like, device-like, and long historical prefixes remain text too.

Selected report/model keys retain their existing portable-name restrictions. Active report model references cannot escape the selected byte map. Mixed historical prefixes, changed selected names, model substitutions, unknown fields, extra/missing/reordered records, counter/outcome/hash changes, and undeclared scope refuse compatibility. All other typed summary fields must match exactly. The existing 1 MiB summary byte budget applies before either comparison; no separate arbitrary historical-prefix length limit applies. Failure cannot mutate computed records or install a declared scope.

A successful compatibility comparison returns the raw supplied summary SHA and per-record historical/selected name bindings. The UI displays recorded locations as escaped text, with no links or access. Raw imported summary bytes remain unchanged. Imported projects remain inert until explicit Run. Normal portable outputs remain unchanged.

Evidence retained so far: a real four-unit native ILP package, explicitly executed native L2 verification, independent exhaustive optimum readback, and absolute/relative/parent-relative desktop production witnesses. Nineteen shared Rust unit tests pass, including oversized-summary refusal, long historical locations, strict metadata equality and active selected-name restrictions. Earlier native/WASM/browser checks exercised the preceding absolute-only prototype; their receipts remain preserved and do not establish acceptance of this revision. Fresh native/WASM and browser checks are required for this revision.
