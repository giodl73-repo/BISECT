## Completion contract

For each claimed capability, record its desktop source/behavior, WASM operation, UI action, supported input scope, tests and remaining limitations. Parsing a flag or offering a button is insufficient.

- Use the actual desktop parser, compositor and shared kernels as authority. Independently check algorithm outputs where appropriate; a native host calling the same adapter alone does not prove CLI orchestration equivalence.
- Preserve original source bytes, argument text, exact integer/seed values and recorded identities. Compare accepted plans/contexts, reports, ZIP contents and failure outcomes, not just success status.
- Keep native parsed-but-unused fields unused. A desktop metadata declaration must not become an invented browser algorithm effect.
- Open is inert. Retained results and imported receipts confer no execution or authenticity authority. Input edits retire fresh exports; replay is explicit.
- Discovery/writes operate within user-selected roots. Cancellation retains completed accepted results. A follow-up failure does not erase a completed partition.
- Full desktop parity remains unproven while required native backends or workflows are unresolved. A useful browser release with documented limits is a separate milestone.

### Workspace safety and recovery contract

WP-03 specifies transitions from selected sources through reviewed requests, running work, accepted/partial outcomes, staged artifacts and installed/read-back-verified outputs. Every source change, project Open, handle revocation or operation change invalidates affected previews and generation tokens. An older worker result must not finalize a newer request or installation.

Recorded paths and imported handles/receipts grant no filesystem authority. Only a currently authorized selected root can be read or written, with normalized relative paths, reserved-name/duplicate checks and native collision policy preflights. Reset/force actions preview their concrete affected scope and require an explicit GUI action for that scope. They never execute from an archive, saved flag or background restore.

Installation stages bounded files, checks exact written bytes, and writes a completion marker last. Browser APIs do not imply an OS-atomic transaction: cancellation, permission loss, storage exhaustion or closure leaves an interrupted journal/staging state, not a completed marker. Recovery is explicit and preserves previous accepted results. Tests interrupt before writing, mid-body, after hashing and before marker commit, including a changed source/root while a write is pending. Re-imported metadata alone cannot establish installed-byte verification.

WP-03/WP-05 also retain the existing hostile-input boundaries: bounded compressed and expanded archives, member/node/depth limits, CRC and duplicate checks, traversal/alias rejection, typed schema/version checks and no executable content on Open. Remote acquisition uses the existing explicit provider/relay boundary with redirect, credential, byte-limit and cancellation checks. No imported URL starts a fetch automatically. Reports and error text remain safely rendered; failure receipts can contain private source data and are downloaded only by explicit user action. Identity hashes provide tamper evidence, not source authenticity, malware resistance or election certification.
