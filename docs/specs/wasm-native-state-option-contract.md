# State option execution contract

The 37 State fields previously marked unreviewed now have explicit, scoped dispositions in `wasm-native-state-option-contract.json` and the engine option inventory. Twenty-four map to the selected prepared engine/source path. Thirteen are explicitly refused orchestration fields on that path. Refusal is incomplete functionality, not proof that the corresponding native CLI effect exists in WASM.

The active fields cover scope/profile/count/tolerance, structure and weight overrides, search selection and budgets, and fixed/adaptive multiscale parameters. Tests assert active compiled values rather than merely observing that an argument parsed. Seven additional whole native-host compilation comparisons cover lowercase state binding, 2000/2010 vintage binding, chamber metadata and mismatches, district count, population tolerance and court profile. The required fresh matrix contains 87 compilations, 61 native retry/export Runs, 24 independent native State kernel matches and 148 complete native-host replies.

The selected prepared path refuses explicit `version`, `output_dir`, `dpi`, `position`, `print_only`, `debug`, `reset`, `manifest`, `force`, `adjacency`, `state_name`, `label` and `time_partition`. Its refusal of `population_source` is also checked; that field already had a separate review explaining native requested metadata versus actual population-vector selection. Fourteen WASM/compiler-host refusal cases verify the complete current guard. These are refusals by the prepared compiler hosted natively, not claims that the desktop State command itself rejects the flags. Some native declarations have no partition effect.

The browser's State command review now displays explicitly supplied refused flags before compilation. Default values do not trigger the notice. The list is generated from `native_state_run.rs` by `native_state_boundary.py`, and build checks refuse source drift. This is an explanatory notice, not a second parser or an execution gate. Other inputs still need compatible selected sources, native policy, backend and numerical validation. No algorithm settings, tolerated values or runtime refusal behavior changed.

`test_native_state_option_contract.mjs` requires the current artifact's execution matrix, validates the option mappings and supplementary scopes, checks the guard and writes evidence. Its ordinary compiler comparisons normalize only native versus WASM count width. `test_native_state_option_contract_browser.mjs` uses real native inspections through a WASM worker, verifies visible explicit refusals, unflagged defaults, edit freshness, inert Open, a 390px viewport and no partition. Existing native command, graph execution and full project UI regressions also pass.

Remaining work includes mapping applicable raw State orchestration flags into the original-source, output and practitioner workflows without inventing effects for native ignored flags. Current tests do not establish every method/source combination, full filesystem equivalence, national original-data capacity or completion of the overall WASM goal. No deployment is included.
