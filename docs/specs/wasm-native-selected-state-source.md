# Single selected-source State Run

The practitioner workbench now has **Run selected State sources (honor district count)**. From native binary, Census or tract preparation, **Use selected sources for a single State Run** selects that mode without inspecting, preparing or executing anything. The project retains the original selected sources, native flags, optional workflow binding and source kind. Open remains inert.

This mode differs from the national source queue: it does not replace state, year, resolution, chamber or an explicitly supplied `--districts`. The native inspector must confirm that the flags match the selected source scope. An explicit count is used; when absent, the shared native chamber resolver supplies it and its complete allocation receipt is retained. Counts follow the existing browser source-job bound of 1–500. A caller-provided conflicting scope count refuses. Sources and flags are snapshotted and hashed before dispatch, then rechecked before source preparation. Unsupported orchestration flags, altered sources and mismatched scopes refuse before preparation or partitioning.

The implementation composes the existing native binary/Census/tract preparation, native State parser/compiler, retry/export execution and selected follow-up stages. Partition algorithms remain in Rust WASM. It does not acquire data or run a national selection. Matching-source recipes now retain the original flags unchanged, including House/Senate chamber settings; see [chamber source support](wasm-native-state-chamber-sources.md). Native `--adjacency` bindings retain all selected binary and companion identities and the original path as intent; they cannot substitute acquired Census data. The existing queue keeps its own scope and congressional allocation policy.

Accepted results include `single_source_selection`: the resolved scope, native or explicit count provenance, unchanged-scope declaration and no-acquisition declaration. Source preparation metadata and hashes remain available; duplicate graph/display JSON strings are omitted because original sources, the accepted exact request and geometry are already retained. The ordinary accepted-run ZIP includes recipe, command/binding, request, plan/context and accepted assignments. Save/Open preserves the source inputs and source kind for an explicit rerun.

Fresh accepted runs expose ZIP, map, output and validation handoffs. Map DPI and output version/layout follow the inspected State workflow binding when present. Mapping and native research-manifest output use the accepted plan without another partition. Validation adopts exact plan/context bytes and removes earlier certificate/lineage inputs; this also fixes the shared handoff's former assignment to the constant project-input container. These actions do not certify the new plan. Reopened results stay inactive until explicitly rerun.

The current original-source boundary is known Census states, congressional/House/Senate chambers, 2000/2010/2020 and tract/block-group/block scope. Single-source mode honors explicit district counts or native chamber allocation; it does not complete international/custom-year/unit State orchestration, desktop discovery/reset/overwrite semantics or remaining refused flags. Full capability parity and authentic national capacities remain unproven.
