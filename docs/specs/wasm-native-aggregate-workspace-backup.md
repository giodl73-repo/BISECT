# Native Aggregate workspace backup

Status: integrated into the maintained working tree after current-source Node, native CLI, actual Chrome and native server/catalog checks. Complete amended builders/package/proof profiles and full WP-01-WP-10 acceptance remain open. This is a local preview, not a deployment.

The workbench offers Download selected workspace backup and Import backup as a new browser workspace. Ordinary Save project retains portable inputs/results/version. Aggregate workspace backup additionally retains all native-root files, scratch content, empty directories and action journals. Import supplies data; it restores no selected handle, runtime trust, confirmation or recovery grant.

Browser workspace labels are small sidecar files beside their UUID directories in the app-owned storage container. They are outside the native data root. Completion writes this label only after all created/imported files have passed readback. Listing reads bounded labels without source bodies and reports incomplete/unreadable roots without hiding valid ones. The count/check/reservation is protected by an exclusive registry Web Lock and includes incomplete roots in the 200-directory limit. Creation and import additionally hold the shared Aggregate application coordination boundary exclusively throughout actual storage writes, so participating inspection/backup cannot overlap a copy.

Stored ZIP32 backup v2 contains workspace-backup.json plus objects/<sha256> blobs. The manifest has exactly schema_version (bisect-native-workspace-backup-v2), workspace (the original descriptive label) and entries. Directory entries have path/kind; file entries also have SHA-256 and byte length. Identical bodies share a blob. Every native file path is data, including a directory or file whose name resembles an application label. No filename inside the native root is reserved for browser bookkeeping. An empty native root is representable by a manifest-only archive.

Draft backup v1 remains accepted. Its manifest has schema_version and entries, and its in-root .bisect-workspace.json file is explicitly defined as selection metadata. Import migrates that legacy marker into a newly generated external label and retains all other native file/history bytes. Normal export writes v2; the explicit incomplete-source path writes v3. The original v1 label remains in the original backup. Imported label fields are descriptive owner claims, not authenticated provenance.

The checked profile is 256 MiB ZIP, 240 MiB across represented file bytes, 96 MiB per file, 4 MiB manifest, 19,000 paths and depth 24. Paths satisfy the existing portable selected-workspace policy. Duplicate/case-colliding paths, missing or differently cased parents, file/directory ancestry conflicts, traversal, reserved unsafe components, unexpected fields, linked/compressed/encrypted/split ZIP members, inconsistent local/central headers, CRC errors, hidden/overlapping extents, missing/unreferenced/wrong-SHA blobs and invalid labels refuse before destination reservation. Parsing takes a private byte snapshot before asynchronous hashes. The ordinary cache/source ZIP profiles retain their own minimum-member policies.

Export closes over a live browser directory and fresh validated label. It holds a shared Aggregate application lock and refuses if a participating native writer is active. It includes unrelated portable notes rather than silently omitting them, rechecks rosters/types and exact-length file hashes, then builds the ZIP without engine execution or workspace writes. These are observed drift checks, not an atomic snapshot against unrelated actors.

Import validates the entire archive before reserving a fresh UUID root; it replaces no existing workspace. It creates directories, copies and reads back each native file, then commits the new external label. Cancellation/failure retains an incomplete destination. Imported journal IDs, baselines, record slots and scratch bytes remain unchanged. Recovery still requires the original trusted loaded WASM, semantic plan recomputation, fresh live prefix checks, a new review and separate confirmation. Terminal/ambiguous/unknown histories refuse; importing data never runs them.

The UI retires previous review/history selections before backup/import. Import selects the new copy and restores its version label, while matching year/current settings still need explicit review. Missing browser coordination disables creation/import/backup/native Apply; portable Run and output ZIP remain available. Project Open restores no root or approval. A selected disk folder can provide portable inputs; actual native moves require supported browser-managed storage.

## Incomplete-source inspection and snapshot

A listed UUID root with missing/corrupt external metadata can be explicitly inspected without completing it. Inspection requests only stat, roster and fileMetadata capabilities and reads native filenames, kinds and lengths, never native bodies or hashes. Bounded external label bytes may be read to establish why normal selection is unavailable. Names outside the portable policy are reported as blocked rather than silently omitted. The report rechecks rosters/types/sizes, but equal-size content drift is outside its scope. Known snapshot-profile reporting includes path depth and a conservative manifest-size allowance as well as per-file/combined byte limits. These checks do not predict content stability or promise export success. It is descriptive data, not a write/recovery grant. If the label becomes valid, a stale incomplete selection refuses and requires relisting.

Explicit unconfirmed snapshot requires current valid version/year scope labels. It reads and validates native bytes using the usual backup bounds and shared Aggregate lock; it leaves the native root and external label untouched. Full-copy exclusive coordination prevents participating create/import from overlapping the snapshot. Unrelated actors are outside this coordination; observed drift checks do not promise an atomic snapshot.

The manifest has the same three keys as v2, but schema_version is bisect-native-workspace-backup-v3. Its workspace descriptor uses bisect-native-browser-workspace-v2 with the usual id/version/year/created fields plus exactly source_status: unconfirmed-creation. Current supplied scope/time are descriptive snapshot/import metadata, not evidence of the original creation settings or completion. Parser enforces v3 if and only if this descriptor has that marker; v2 downgrade and v3 marker removal refuse. Import generates a fresh UUID, copies and reads back bytes, retains the unconfirmed marker in its new external descriptor, and reexports v3. Copying successfully does not clear uncertainty about the original source creation. Neither label is authenticated provenance.

The workbench presents incomplete roots separately with explicit Inspect available files and Download unconfirmed snapshot controls. It renders filenames/sizes/reasons as text, keeps marked imports visibly unconfirmed, and retires the inspection and selections on project Open/context changes. Import does not execute journals or confer confirmation. Coordination unavailability permits read-only metadata inspection but disables creation/import/snapshot/native writes; portable Run/download remains available.
