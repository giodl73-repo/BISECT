# NRS v0.3 Block-Level Ensemble Gate

**Protocol ID:** `nrs-v0.3-block-ensemble-gate-v1`

**Frozen:** 2026-08-10, before any governed block-level ReCom chain

**Status:** frozen; input adapter and preflight required before execution

## Question

Can the verified 2020 NRS v0.3 block assignment initialize reproducible ReCom
chains on the same hash-bound block RCTX, and do the preregistered scalar and
partition-space diagnostics support a bounded ensemble comparison?

This is a feasibility and sensitivity gate. It is not a national neutrality,
fairness, legal-validity, optimality, or feasible-space-completeness test.

## Frozen Inputs

| Field | Frozen value |
|---|---|
| Census year / chamber | 2020 / congressional |
| Atomic units | Census tabulation blocks, including the governed bridge edges |
| Context | `data/2020/certified/<state>_blocks_2020.rctx` |
| Starting plan | `runs/nrs-v0.3/neutral-analysis/national-2020/states/<state>/package/baseline_assignments.json` |
| Population | RCTX total population |
| Population tolerance | 0.005 relative to equal district population |
| Primary kernel | Wilson uniform spanning tree |
| Sensitivity kernel | GerryChain-compatible random-weight Kruskal tree |
| Chains per kernel | 4 |
| Steps per chain | 2,000 after the initial state |
| Burn-in | first 500 steps discarded |
| Snapshot stride | every 10 steps |
| Base seed | 20260810, with `bisect_ensemble::chain::chain_seed` derivation |
| Execution | one state and one chain active at a time |

The two kernels define separate sampled distributions. Their draws may not be
pooled. The Kruskal sensitivity kernel is not described as an independent
software implementation.

## Stage 0 - Input Adapter And Excluded Preflight

Before any governed chain, a dedicated adapter must:

1. parse RCTX directly rather than translating through the tract pickle format;
2. require `unit_kind=block`, State/year agreement, unique sorted GEOIDs, and
   equal unit/population/adjacency lengths;
3. require in-range symmetric undirected adjacency and finite nonnegative edge
   weights;
4. join the starting assignment by GEOID, require exactly one positive label
   per RCTX unit, consecutive labels `1..k`, no extra assignment keys, and the
   apportioned district count;
5. audit every starting district for nonemptiness, RCTX contiguity, and the
   frozen population tolerance; and
6. bind the adapter source, executable, RCTX, assignment, and protocol hashes.

An excluded 25-step run per kernel on Rhode Island may measure wall time,
peak memory, crashes, acceptance, and trace shape. Those steps are engineering
preflight only: they may not enter a percentile, convergence diagnostic, paper
table, or stopping decision. Failure requires retaining the preflight artifact
and remediating the adapter or kernel before governed execution.

## Stage 1 - Governed Rhode Island Slice

Rhode Island is the first and only initially authorized State: two districts,
25,649 blocks, and an already verified NRS v0.3 starting package. Execute Wilson
first, chains 0 through 3, followed by Kruskal, chains 0 through 3. No chain may
be replaced, extended, or rerun under a different tolerance after metrics are
observed.

For every step retain acceptance, unweighted cut edges and cut fraction,
RCTX-weighted boundary cut, maximum population deviation, and runtime. Retain
the canonical assignment at every snapshot. The baseline uses the same metric
implementations.

## Diagnostics And Decision Rules

Analyze each kernel separately after the frozen burn-in:

- split-chain R-hat for unweighted cut fraction and weighted boundary cut;
- per-chain and pooled ESS for both scalar cut metrics;
- acceptance rate and maximum population deviation;
- label-aligned Hamming-distance autocorrelation and integrated
  autocorrelation time from snapshots; and
- cross-kernel mean, standard deviation, quantiles, and two-sample KS statistic,
  with the KS p-value treated as descriptive because draws are autocorrelated.

A kernel is labeled converged only if both cut metrics have R-hat below 1.05
and pooled ESS at least 100. No tail statement below 1 percent or above 99
percent is allowed unless the relevant ESS is at least 1,000. Passing R-hat and
ESS does not prove mixing or independence.

The Stage 1 gate passes only if all eight chains complete, every recorded plan
meets population and contiguity invariants, package verification passes, and a
fresh sequential rerun regenerates normalized metrics and canonical snapshots
exactly. Convergence is reported separately: a valid but non-converged run is a
negative empirical result and does not authorize percentile claims.

## Expansion Gate

No multi-State or national execution is authorized by this document. A later
version may precommit NH, NM, and GA only after Stage 1 reports measured
time/step, peak memory, trace size, acceptance, and diagnostic behavior for
both kernels. That version must set an explicit total compute and storage
budget before execution. It may not select States or kernels using observed
benchmark percentiles.

All 44 multi-district States remain the eventual target cohort, while the six
one-seat States remain design exclusions. Full-cohort language is prohibited
until every scheduled State completes under a separately frozen sequential
protocol.

## Evidence Package

The package must contain the frozen protocol, input audit, commands, software
and source hashes, per-chain traces, analysis, flat summary, deviations,
manifest, and verifier. Raw RCTX files may remain source-custody references
when their already published SHA-256 values are bound by the manifest.

The verifier must re-hash every local input, replay all input audits, recompute
all metrics and diagnostics from traces, reject missing or replacement chains,
and compare a fresh sequential execution with normalized committed outputs.

## Claim Boundary

Stage 1 can support only a Rhode Island block-graph ReCom feasibility and
kernel-sensitivity result under the frozen NRS v0.3 start, tolerance, metrics,
and seeds. It cannot establish national representativeness, neutrality,
partisan or demographic fairness, VRA compliance, polygon compactness, legal
validity, exact objective proof, sampler equivalence, or that the chains cover
all valid plans.
