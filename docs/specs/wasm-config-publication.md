# Config publication to a selected folder

Date: 2026-10-27. Status: bounded implementation and component/browser checks
pass. Config parents and acceptance-v1 remain partial.

After generating YAML, choose **Review destination**, select a folder, inspect
the path/action and SHA-256, confirm, then write. Blank output uses
`configs/<generated_filename>`. A relative path changes the destination within
the selected root. Existing destinations refuse without force; that refusal
does not read the existing file. Force requires a new review showing its hash.
The generated bytes are recomputed in a fresh native worker before review.
Successful publication requires exact byte-length/SHA readback.

This adapts the actual `config new` writer in `crates/bisect-cli/src/algo_config.rs`:
create missing parents, refuse collisions by default, replace explicitly with
force, and bypass destination IO for dry-run. The native writer uses an existence
check and `std::fs::write`; neither implementation promises an atomic no-clobber
transaction. External writers can race observations and writes.

Dry-run still recomputes native YAML, but never opens a picker, checks permission,
lists a directory or reads/writes a destination. Like native dry-run, it ignores
the output path as a filesystem instruction. Bounded otherwise unsafe output
intent may be retained as inert text in this mode.

## Authority and interrupted effects

Only a private, live, single-use review holds the selected root and generated
bytes. The apply step rechecks source revision, settings, result identity,
permission, parent roster and destination identity. A changed destination requires
a new review. Changes to project/template/output settings retire the review.
Imported/serialized/cloned/consumed reviews grant nothing. Save/Open retains
only optional closed `{path, force, dry_run}` settings; Open performs no worker,
picker or destination calls and restores no folder, review or write capability.

Cancellation can leave created parents or an empty/changed file. Receipts record
attempted paths, created parents, possible effects, file creation, writable and
write requests, completed close and verified readback separately. A close followed
by cancellation is not a successful verified publication. Failures do not delete
partial effects or automatically retry. A remaining empty file triggers ordinary
collision refusal; replacement needs a fresh explicit force review. Progress
observer exceptions cannot change publication. Duplicate handler calls return
before entering the active operation's cleanup.

Receipts are downloadable historical JSON, not authority or source-authenticity
proof. No permission is silently requested again. Unsupported browsers retain
ordinary YAML download and destination-free dry-run.

## Explicit bounds

Write paths use the existing portable ASCII package path rules (240 characters),
at most 16 segments/200 characters per segment, no traversal, case aliases,
Windows reserved device names or trailing dots/spaces. Each observed directory
is limited to 20,000 entries. Existing replacement files are limited to 8 MiB;
generated YAML to 256 KiB. Settings path intent is bounded to 4,096 UTF-8 bytes
without control characters. These constraints are a browser adaptation, not
unrestricted native-path parity. Checks do not establish publisher authenticity,
legal certification, OS transactions or protection from compromised page code.

## Windows sharing-lock regression

The maintained Windows-only gate `scripts/web/test_config_publication_windows.mjs`
accepts `--reference=<actual Config CLI case root>` and optional `--repo=<checkout>`
and `--profile=<name>`. It binds the actual native executable and WASM bytes from
that reference. An owned-file helper holds a Windows FileShare.Read lock without
changing ACLs. The native CLI and real-file directory facade must refuse writes
and preserve the old bytes. After release, the CLI must succeed; the facade must
reject its consumed review and succeed only after a fresh review, with exact YAML
readback. Helper exit status and original, locked and completed bytes are retained.

Both retained profiles pass this standalone gate. Both registered legacy profiles
and the final packaged C builder register it, with a separate `windows_host`
receipt. Non-Windows hosts report not-run. Registration is not a new complete
builder pass. This exercises Windows file sharing through the native CLI and a
Node directory facade. Actual browser selected-folder grants, cancellation and
revocation, other operating systems and native OS atomic transaction equivalence
remain unverified by this test. No parent acceptance is promoted.
