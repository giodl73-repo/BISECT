# Selected native unit and source identity

This candidate extends selected-source recorded replay while preserving native unit conventions. It does not change the partitioner, seed, retry policy, tolerance, source data or generic custom-graph county contract. Main adoption and complete release acceptance remain pending.

Two optional fields extend PreparedGraph schema version1. `native_source_identity` defaults to false and is omitted when false. It selects native unit-format/report semantics through the shared native weighting compositor; it is a computational policy, not source or jurisdiction authentication. Explicit county overrides are refused. Generic Census and custom graph validation remains unchanged when the field is absent. The native policy preserves the desktop's explicit-adjacency treatment of source IDs, including a state label that does not match their Census prefix.

`native_geoid_index` defaults to absent and is omitted when absent. Its JSON member names are canonical unsigned decimal strings, checked as u64 and bounded to the selected vertex range. It is permitted only with native source identity. Absent means the complete original index is the supplied ordered unit IDs. An explicit empty object records no original source IDs; a partial object records only originally present entries. For a missing entry the native output unit ID is the vertex ordinal string. That output label does not become an invented source GEOID or county identity. Explicit index values must agree with the output IDs and native ordinal fallback.

Native COI, partisan, demographic, character and subdivision weighting use only the original present source IDs. Report county prefixes likewise derive only from present source IDs. In particular, a large numeric ordinal cannot manufacture a five-digit report county, and COI factors named after ordinal fallback labels cannot affect units whose original source ID was absent. Raw selected source bytes remain retained and are checked against the recorded native graph digest before constructing this typed mapping.

Original RPLAN output kind follows the actual desktop builder's plan_resolution convention. Current ordinary block and block_group runs can export the native Imported fallback; replay retains that identity rather than correcting its meaning. A fine projection changes the native output kind to block group even when the recorded recipe retains the seed configuration's tract plan_resolution. The shared native unit-format validator, source index, ordered graph, physical weights, populations and report counties are checked before generation; exact selected original RCTX and plan body are restored after physical-export checks. New label/time remain new metadata. Auxiliary retained context fields remain selected claims.

The two fields preserve legacy serialized requests when absent. Older engines may refuse requests containing the new fields. Project Open remains inert, retains raw inputs/results and grants no source, execution or filesystem authority. Replay is explicit; source/input edits retire fresh exports and receipts. The existing local project, receipt size and source byte limits are unchanged.
