# Ceremony Start from original sources

Date: 2026-10-27. Status: implemented with bounded native/default/C-enabled and
actual browser evidence. The complete updated builder passes; broader acceptance remains open.

Choose **Start ceremony from original rule profile**, select the complete tree
and original profile, then enter genesis time, review interval, witness minimum
and receipt IDs. Run hashes the exact profile bytes, derives the configuration
and calls the existing native Rust Start kernel. Reading candidate count/hash
fields in JavaScript grants no authority: native Start verifies the complete
original tree and root binding before returning a transcript. Tree text is never
reserialized through JavaScript. The generated-tree handoff selects this form;
prepared-configuration Start remains available.

Genesis is canonical signed i64 text; review duration retains the full native
u64 domain as canonical text. An unnecessary signed-range Rust browser guard
was removed after actual CLI Start accepted the u64 maximum and the old browser
refused. Raw digit assertions prevent rounded JSON comparisons from hiding loss.
Maximum-review Verify/Halt succeed and an unreachable announcement fails in both
native/browser checks. Durations are neither clamped nor converted to JS numbers.

Binary and empty profiles are valid native hash inputs. A dedicated closed
name/base64 validator preserves them without widening generic election-source
readers. Limits remain 3 MiB per tree/profile, 2–24 exact-tree units/seats and
100 receipts of at most 2,000 UTF-8 bytes. Unrelated edits preserve imported
receipt strings, including whitespace, carriage returns and empty entries.
Editing the receipt textarea explicitly uses one ID per line.

The optional `ceremonyStartInputs` project field retains profile bytes and exact
settings. Unknown keys, noncanonical base64 and integer overflow refuse Open.
Ceremony text decoding preserves a UTF-8 BOM rather than silently stripping it:
the actual CLI and browser both refuse such a JSON tree. Original failure input
bytes remain available in the project/request; generic text readers are unchanged.
Open never executes, fetches a rule profile or restores a filesystem capability.
Loaded results stay unverified. Edits retire transcript export; invalid drafts
and pending file reads block Run. Size checks precede reads, and cancellation or
project/operation changes retire late reads. Result tables show recorded source
hashes, byte count and exact timing values; raw result JSON retains config text.

native transcript values/downloads, inert Save/Open, retained failures, late
