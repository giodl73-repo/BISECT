# Custom selected-source State Runs

The single-State browser action now connects selected precinct/imported native binaries to `prepare-native-adjacency-state-run`. It retains the original argument array and hashes the entire source recipe. Its `source_scope_policy: match-native-adjacency-flags` is distinct from the known-Census matching-flags policy. The shared Rust boundary validates the supplied binary and companions, matching state/year/chamber and adjacency basename before applying native adjacency year/resolution semantics. No argument path is opened.

Select the native binary, ordered IDs, centroids/geometry as required and an aligned county companion. Choose precinct/imported, a two-uppercase-letter jurisdiction and four-digit year. Enable State flags, select single State Run and provide matching `--state`, `--year`, `--chamber`, and `--adjacency` naming the binary. Supply `--districts` when the native chamber registry has no matching count. The default-flags action includes the selected adjacency filename. Run is explicit; selection and Open do not prepare or partition.

The browser uses the compiled request through the existing prepared review/execution/export path. Custom prepared scope is accepted only when the original request graph carries matching custom unit kind, state and year. Exact u64 seed strings and request bytes remain intact. Accepted output retains the immutable original source recipe, native review, byte/hash receipts, district-count provenance and physical RPLAN/RCTX. Review shows the seed and confirms the recorded adjacency path was not opened.

Custom source jobs cannot enter the national queue, including through imported queue JSON. Source workbench archives restore custom metadata, original command and selected bytes in single-State mode without execution. A changed source recipe fails before compilation. The subsequent [custom State workflow extension](wasm-native-custom-state-workflow.md) connects verified output bindings and optional accepted-plan follow-ups. Output defaults to labeled layout, which supports jurisdictions outside the state catalog. Matching supplied GeoJSON joins exact custom unit IDs. Custom county-split analysis now uses complete matching RCTX county identities through the shared explicit analyzer. Missing or misaligned identities remain visible failures and retain accepted exports; missing optional election inputs can still leave a partial follow-up.
