# Custom State output bindings and follow-up stages

Selected precinct/imported State runs accept the explicit State source/output handoff and optional accepted-plan follow-ups. The native binary/companions, two-letter jurisdiction, four-digit year, chamber and exact seed retain their validation and identity boundaries. The original handoff added browser orchestration; the subsequent explicit county-split extension also updates shared Rust/WASM analysis. Partition algorithms remain unchanged.

Inspect the original State flags with selected source files, then use **Apply inspected State source/output choices**. This records `--version`, `--output-dir`, `--label`, `--manifest` and `--dpi` as browser workflow choices while retaining the original argument text and hashes. The output path is intent only. The selected adjacency basename must match; source preparation bytes are hash-bound. Custom units bypass Census resolution lookup as the native adjacency path does. Known-Census handoffs still require matching resolution.

The canonical engine command omits mapped workflow flags. Before custom execution, the shared binding recheck inspects the original and canonical commands, checks native algorithm/profile equality, unmapped field equality and source identities, and refuses unsupported flags. Only then does the custom compiler wrapper restore the verified `--adjacency` path argument for the typed Rust selected-source API. That API reads supplied bytes, never the argument path. A changed binding, companion or source scope refuses before partitioning. A custom binding without selected adjacency identity is rejected.

Custom bindings default to labeled output, including when no explicit CLI label was supplied. The accepted export label must still meet the existing portable output-name rules; the workflow does not invent or sanitize it. Export label changes require a new Run. Native folder preparation/install remain separate explicit actions.

Optional analysis, maps and reports use the accepted RPLAN/RCTX through the shared follow-up implementation. They never partition again. If follow-up setup fails, the accepted plan and exports remain available with a workflow error. Partial workflows retain completed files and the native failed-stage detail. The guide and prepared-State result tables now show partial/failed follow-ups, including nested analysis steps. A fresh workflow has a direct **Download available workflow files** action; Open does not authorize that export until fresh execution/checking.

The prior Census-only county-split limitation is now addressed by the shared
[explicit county identity analyzer](wasm-explicit-county-splits.md). Complete
matching RCTX county IDs support custom units such as `ward-A`; missing or
misaligned identities still refuse analysis. These fixtures now compute county
splits and retain the county-map identity hash. Their analysis stage remains
partial because optional election data are unavailable, while maps and reports
complete. A map-only workflow completes.
