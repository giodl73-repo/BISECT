# Doctor selected-plan command reports

The plan inventory offers optional native Doctor report controls for `--all` and
`--label`. Users select a plans collection, enable the controls, choose a mode,
and explicitly Run. The existing Rust plan-doctor interpretation supplies analysis
status and summaries; the browser supplies the complete console report and a text
download. JSON export includes the optional `native_doctor` report.

The optional closed `planDoctorInputs.command` recipe contains mode, label,
output_base, version and year. Prefix fields are bounded display text, never paths
to open. Label mode interprets only the selected plan. All mode ignores an unused
label, matching native dispatch. Old projects without the recipe keep their prior
behavior. Save/Open restores data without running or granting filesystem access.

Changing settings invalidates results. An invalid draft blocks Run and export
instead of silently using the last valid settings. Reloading the selected source
preserves the command recipe. Only a fresh explicit Run enables report download.

## Native comparison boundary

Supported successful reports match actual native CLI console bytes, allowing only
path separator changes in the displayed `Dir:` or empty-collection path line.
`reference_cli_exit_code` describes the comparison, not a browser native process.
Native exit 0 can contain `[FAIL]` rows and missing required analysis; completion
is not validation. Presence of maps, audit or RPLAN files does not establish their
validity, source authenticity, or legal/court readiness. The native section labels
are reproduced, not independently endorsed.

Invalid, missing and unreadable manifests produce explicit adapted diagnostics
with a null reference status. No native failure status or OS error is guessed.
A native 64-bit manifest can accept a pointer-sized district count such as
4,294,967,296 that the existing wasm32 schema refuses. That case is explicitly
unsupported, not counted as an equivalent native refusal.

Actual native dispatch gives verify-manifest priority over tutorial, then all,
label, and location modes. Dispatch probes establish this ordering, not complete
acceptance of verifier/tutorial workflows. Their existing browser operations
remain separately mapped and require source/runtime reconciliation.

Native location Doctor is also still missing as a complete browser workflow.
Its registry consults primary/alias overrides, then a home policy, then embedded
data. Chamber tolerance uses a separate loader without the home fallback.
A controlled home fixture therefore selects a nine-seat registry entry while
retaining embedded tolerance; explicitly selecting that same policy uses its
twelve-percent tolerance. The existing browser location-input preflight is a
different explicit-input contract. Native manifest fallback, adjacency V3/V4 and
bg/tract discovery, and TIGER directory-presence checks remain to be reconciled.
Directory presence must not be described as geometry validity.
