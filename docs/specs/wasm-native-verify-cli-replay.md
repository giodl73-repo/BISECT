# Actual native Verify replay output root

A real CLI State/Verify control found a native desktop path mismatch. Verify invoked State with an explicit output-dir equal to the base, so State wrote <base>/<year>/plans/<label>. Verify then attempted to read <base>/verify/<year>/plans/<label>/data/final_assignments.json. The replay could complete successfully and still report a missing assignments error.

The candidate passes <base>/verify as the child State output-dir using a Path argument. This matches the existing versioned loader; no directories are precreated to make verification appear successful. Original-reference discovery, sidecar prechecks, literal assignment agreement, threshold and failure behavior remain the same. In particular, this patch does not activate seed/balance fields that the actual native child invocation currently omits, or claim that its printed equivalent command is a complete replay specification.

The dedicated test scripts/web/test_native_cli_verify_replay.py regenerates the four-unit synthetic RI binary/companions from maintained fixtures, runs actual State to produce an original native manifest/certificate/assignments, and invokes actual Verify without --dry-run. It covers exact replay success, a deliberately changed original-reference assignment failing agreement after replay, and an altered certificate refusing before replay. Output roots include spaces and a Unicode character. File and directory rosters and original source/native-baseline bytes remain unchanged. Every invocation, raw stdout/stderr and binary/test/fixture identity is retained in a unique owned run directory. A supplied broken binary fails the exact-replay control with the original missing versioned file error.

All three builder candidates register this native CLI regression. C preview uses its separately owned core CLI path for the check, preserving the prior backend-reference separation. The one-district control exercises no METIS partition; this is neither C/Rust assignment equivalence nor broader Verify workflow acceptance.

Evidence is under target/native-verify-cli-replay-20261101: observation.json and red-regression.log retain the native failure; candidate-build.log records a dedicated no-default-features debug build from a source-isolated replica; green-regression logs and independent readback identify the corrected outcome. Main sources remain frozen by R13 and this candidate is not adopted. The existing browser Inspect/explicit replay UI has its own unchanged scoped contract. Real multi-district/max-u64/nondefault parameter, browser workspace replay/installation, other backend/method/source, actual host, full amended builder/package/proof and original WP-01-WP-10 acceptance remain open.
