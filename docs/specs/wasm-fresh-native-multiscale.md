# Fresh native multiscale runs

The fresh State API can prepare and execute native64 multiscale and adaptive
multiscale runs directly from selected raw sources. No original plan, RCTX or
recorded recipe is supplied to execution.

In the fresh-source panel, select **Use native64 multiscale sampling** and supply
matching State search/level flags. Tract/county runs use the primary graph.
Block-group runs additionally require selected fine adjacency and GEOID files;
fine centroids are optional. Both source scopes must match. The native State
compositor controls steps, percentile, adaptive settings and population retries.
Review remains inert and Run is a separate action.

For an explicit `c-ffi` request, use a C-enabled package and select the explicit
C runtime load control. Open/Review do not fetch the SDK. The multiscale reference
with that flag matches its native output, but instrumentation records no C bridge
calls in this dispatch; sidecar attachment is not claimed as C computation.

The Rust input adds optional `multiscale: {sampler, fine_source}`. The supported
sampler identifier is `rand-0.8.6-smallrng-native64-wilson`. Native32 currently
refuses explicitly. Omitting multiscale preserves the existing ordinary input
hashes and exports. Fine output uses native BG unit construction, complete fine
populations and physical Boundary edges. Conventional `adjacency` and companion
hashes identify the physical output graph; separate `browser.native-primary-*`
roles retain the coarse computational sources. No original native recipe digest,
source authenticity, report observations or legal certification is invented.

Sampler choice, selected fine files and C load intent are retained by regular
project/archive/autosave flows. Imported results remain unverified data; viewing
them cannot authorize current exports. Seeds are shown from the nested executed
multiscale request. Display polygons remain separate from native report geometry.

Maintained evidence uses the two existing actual32-BG native references plus
additional actual16-tract county-coarse/adaptive references. All retain64steps,
seed17,7.125% tolerance,0.5 percentile and niter100. Three references run in the
core profile; the additional unchanged C-flag reference runs in the C-enabled
profile with its explicit verified sidecar. Five preparation/refusal controls
pass per profile. Ordinary regressions retain twelve cases/fifteen refusals per
profile. Seven full-browser workflows cover16 explicit runs, maps, downloads,
project/plain/compressed archive round trips, autosave/restore, delayed-worker
Open refusal and cancellation recovery. This is fixed-source scope, not a
full-state or all-method capacity campaign.

The target-bound prototype and all failed attempts remain retained privately.
The maintained fixtures/loader/tests use repository-relative paths; absolute
paths inside input/reference metadata remain inert labels. Both builders register
the maintained gates. The reviewed source union is adopted locally. R19 remains
failed at a missing original label-import fixture; a complete amended build is
still required. Broader fine/block/custom/native32, optional native
observations, lifecycle/capacity/authenticity and original full release acceptance
remain open. See the [role review](../../signals/roles/check/fresh-native-multiscale-roles-check-2026-11-03.md).
