# Source-bound recorded fine replay exports

This candidate connects a freshly matching recorded replay to exact plan/context/evidence downloads and explicit audit/map handoffs. Importing a project or receipt grants no execution or filesystem authority. A handoff does not run the engine, audit or map. The UI checks current result ownership and revision after asynchronous hashing; a source-setting edit retires the handoff.

For recorded multiscale BG replay, the selected original RCTX must first match the original plan's complete ordered unit index, fine graph IDs/populations, ordered native adjacency, boundary edge classification, physical weights and county membership. Fine context must not inherit tract seed geometry. Only selected package-relative bytes are read; native paths are never followed. Existing manifest/recipe/source checks still run first.

The exported RCTX retains its original bytes, source identity, classifications and context hash. The regenerated plan body uses that original unit index and retains literal one-based/zero-based label conversion. RPLAN metadata carries the new replay label/time; the whole RPLAN file is therefore not claimed to be the original file. Provenance records the context binding and intermediate export hash. Optional original context auxiliary fields remain selected claims, not regenerated/authenticated source facts. Generic supplied/ordinary exports retain their existing conversion semantics; this candidate does not establish original-context byte parity for every Run path.

`files.nativeRecordedReplayReceipt` is an optional opaque source envelope capped at 8 MiB. It retains comparison, source/backend/execution evidence and SHA-256 bindings of the exact exported text. Opening it checks envelope/size and never interprets the payload as commands or trusted run evidence. Old projects remain valid. A fresh matching result and valid physical export are required for the new actions. Failed-run JSON remains available through the ordinary result download.

The old native map test adapter inserted GEOID while retaining geoid, causing its own duplicate-alias failure. The original failure and binary remain. A new direct native reader/render example consumes the unchanged lowercase source successfully. The corrected adapter accepts matching aliases and refuses conflicting ones. No source coordinates, IDs or native geometry tolerances were changed.

Validation is the complete original 32-unit/two-district core/C native64 replay fixture with requested seed, retries and sampler intact, plus the separately declared exact binary-coordinate geometry and retained original invalid geometry controls. Three native Rust tests include seven rehashed semantic mutations. Each profile passes 26 maintained runtime checks and eleven browser checks (eight explicit worker Runs), exact native postprocessing/PNG comparison, and the existing thirteen-case replay regression. Independent Python checks all original context fields/bytes, plan body, literal labels, populations/BFS and eight retained projects across profiles. Both package asset trees remain unchanged.

The fine-context correction was adopted and verified in the main workspace after R15 became terminal; the original private-stage evidence remains retained. The selected ordinary-context extension is documented separately in [its contract](wasm-recorded-ordinary-context.md) and now has fresh main-source host/core/C runtime/browser validation. R17 is terminal-failed at a fresh-parent test setup error; its completed checks and dependent packaging/proof refusals remain retained. Complete amended builders, fresh release evidence and full ledger acceptance remain required. Original WP-01–WP-10, real-source successful medium/large/national cases, broader ordinary/fine export, host/lifecycle/capacity and acceptance-v1 obligations are unchanged. No deployment/merge is implied.
