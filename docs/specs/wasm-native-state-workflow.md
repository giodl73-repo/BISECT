# Native State output choices

After inspecting a native State command, **Apply inspected State source/output choices** explicitly moves `--version`, `--output-dir`, `--label`, `--manifest` and `--dpi` into browser workflow settings. It can also bind `--adjacency` to selected native binary sources as described below. It retains the original command and its hash and creates separate canonical engine flags from the actual native parser's field values. Other explicitly supplied flags remain present. Native defaults remain defaults. No source preparation, partition or filesystem operation occurs during this handoff.

The version initializes native output settings. An explicit portable label sets graph/template export metadata and selects labeled output; no explicit label leaves the selected export label unchanged and selects state layout. Label or manifest requests enable the existing optional native-output stage for streaming. Existing output preparation produces the shared native research manifest after an accepted Run; it does not create an audit certificate. DPI updates the separate browser workflow's selected map DPI without enabling maps automatically. The current State CLI's declared DPI is not a partition setting; this choice is applied to the shared native map renderer only when that browser stage is selected.

`output_dir` is recorded as intent. It never opens an OS path or determines which file bytes are read. Source files, local output roots and installation remain explicit browser selections. This does not reproduce desktop path discovery, deletion or overwrite semantics. Native output version/label safety limits still apply. A single explicit label cannot install several streamed states into the same namespace; that case refuses before acquisition, allowing distinct per-state labels or state layout to be selected instead.

An explicit `--adjacency` can now select the existing local native binary source workflow. The user must first select the exact `.adj.bin` basename named by the flag and its companions; the browser never opens the path. The complete native preparation input, including every selected companion and declared scope, is hashed into the optional `source_override` binding. Apply selects the native-source panel and enables State source mode, without preparation or execution. Queue and Run check those exact bytes again. An acquired Census source or an unrelated prepared graph/template cannot substitute for that binary. Source workbench exports restore the selected originals and binding inertly. Pending file reads block handoff and queue actions; Open retires a late selection.

This adjacency bridge matches the selected known state, 2000/2010/2020 year and tract/block-group/block resolution. The queue resolves its congressional allocation. The separate [single selected-source State Run](wasm-native-selected-state-source.md) supports congressional/House/Senate chambers, honors explicit district counts and otherwise retains native chamber allocation provenance without changing the selected flags. International/custom-year/unit orchestration, desktop companion discovery and `--state-name` behavior remain incomplete. Other explicit orchestration flags still refuse. The full prepared engine remains a separate path for its supported custom graphs. These limits are remaining parity work, not claims of complete native `--adjacency` support.

The handoff is retained in projects, source jobs and exported recipes. Source and engine command hashes bind exact text; native reinspection verifies the canonical values, effective algorithm and profile before execution. Label or follow-up DPI changes, altered bindings and stale engine flags require reapplication or explicit detachment. Detachment leaves current controls and already queued recipes unchanged. Source projects restore the original command link, output choices and DPI without loading directories or running anything.

The prepared compiler's existing refusal guard is unchanged. A normal compilation still refuses the original orchestration flags unless they are explicitly moved through this handoff. Unmapped flags remain refused. Bound jobs reject them before source preparation; streamed State workflows also check before downloads. Dry-run, reset and force flags are not silently removed or executed. This is a browser workflow adapter, not a claim of complete native State command orchestration.

Queue-only acquisition now shares that preflight for both single-state and bulk staging. A separate Rust WASM inspection worker checks original/bound flags before downloads or queue checkpoints and terminates on success, failure or cancellation. The UI pins its artifact to the loaded engine. Bulk staging and streaming reuse private cloned inspection replies only for exactly matching requests in their immutable snapshots. This avoids starting another WASM instance for every state. These checks inspect flags; source parsing and partitioning remain separate explicit actions. Native Run/States retain their existing orchestration paths.
