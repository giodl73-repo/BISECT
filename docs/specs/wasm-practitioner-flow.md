# Practitioner workflow guide

The workbench now leads with five steps: open/select, settings, Run, review and save. Four workflow choices open one-state configured Run, selected-source State Run, a multi-state batch or exact RPLAN validation. An explicit acquisition shortcut opens the existing source workflow. Input links focus the relevant controls instead of the retained-analysis panel. All specialist tools, TUI navigation and native settings remain available.

`practitioner-flow.js` delegates to existing handlers rather than implementing another engine or persistence path. Choosing a workflow never prepares sources, downloads data or runs an engine. Choosing selected sources explicitly enables single-State source mode through the existing controls; original source bytes and command arguments remain intact. National batch mode still needs prepared jobs or a separate acquisition step.

The guide mirrors runtime, busy and existing action availability after the workbench updates its controls. Run is always an explicit click. A fresh accepted result exposes the existing map handoff and result download. The exact native seed is shown from the shared command review's original string values. Map handoff retires the prior fresh result and still requires an explicit render; it never partitions again. Saved results are labeled unverified on Open, with review/map/download actions unavailable until a fresh check or execution. Archive and project pickers use the existing bounded readers.

Engine identity, keyboard instructions and full JSON are expandable technical details. Live navigation status, failures and native command review remain visible. This is a guide over the existing forms, not a claim that every specialist tool has been redesigned or all WASM parity is complete.

End-to-end validation (`test_practitioner_flow_browser.mjs`) uses real Chrome and WASM with the native-checked custom-source fixture. It checks all four inert routes, source-mode handoff and input focus, original project Open, one exact native-equal Run, busy guards, maximum-u64 seed visibility, byte-equal result ZIP, archive Save/Open with unverified-result retirement, explicit equal replay, and an accepted-plan map without another partition. It verifies advanced JSON access and 390-pixel layout; desktop/mobile screenshots are retained under `target/practitioner-flow-browser`.

This test found shared object references between custom State receipt fields. The archive serializer correctly refused the repeated objects. The custom result constructors now clone those small receipt fields, preserving identical serialized content without changing archive validation. `test_native_custom_state_sources.mjs` also archives and restores each live completed result before JSON serialization, which catches this class of regression.

Existing navigation tests pass, including shortcuts, tool search, native Doctor comparison, focus restoration, busy messages and inert Save/Open. Its library-to-Compare expectation now matches the already implemented retained assignment/analysis handoff. Custom State worker/ZIP tests also pass. Both build scripts gate the new guide browser test after generating its native-checked fixtures.

No Rust algorithm or WASM binary changed in this UI milestone. Local package checks and artifact identities are recorded in the parity audit. Cloudflare deployment is separate.

## Required selections and failure recovery

The guide now lists required source selections for its four primary routes. Configured Run needs YAML and a prepared graph; selected native sources need an adjacency binary and ordered IDs, plus an aligned county companion for precinct/imported units. Census/tract sources need the selected polygon, projection and PL94 sources. Census 2000 retains its native geography-only population path. Batches need jobs and exact plan review needs RPLAN. Optional native geometry mode gains no unconditional centroid/geometry requirement. Other specialist tools retain their own validation paths.

These are presence hints, not file inspection or certification. The checklist never parses source content, computes a graph or replaces native scope, settings or method validation. Missing selections disable only the guided Run button and expose a link to the first missing control. Existing expert controls and native error checks remain authoritative. Focusing a file picker preserves its keyboard tab order and does not open it automatically. Expanded technical details remain available.

Transient failures now appear in the guide with the native message and links back to the current inputs or State flags. Selected filenames are displayed as text and wrap on narrow screens. A fresh existing worker failure receipt can be downloaded explicitly. Input changes or project restoration retire the transient guide error; a new explicit Run is still required. The guide does not retry automatically, change flags, clear sources or loosen file validators. `finish()` now re-enables the underlying Run control before refreshing dependent UI, so failure recovery cannot leave the guide reflecting an earlier disabled state.

`test_practitioner_inputs.mjs` checks required-source combinations, the Census 2000 exception, optional geometry, immutable source metadata, uninspected contents and actual HTML control targets. The browser test additionally checks empty first-run gating, focus/tab order, a 198-character filename at 390-pixel width, a real native adjacency-basename failure, original failed-request hash equality, explicit repair and successful native-equal replay. Existing navigation and custom-source browser/ZIP regressions pass. Worker failure tests separately retain their original native/independent CLI failure baseline. The primary guide test remains a small synthetic scenario, not evidence of every real dataset or algorithm combination.
